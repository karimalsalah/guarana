# Guarana: full reference

> Open-source (GPL-3.0-or-later) Nintendo Switch 2 emulator fork tuned for integrated GPUs: Intel Arc first, AMD Radeon handhelds next. This file collects every fact on https://karimalsalah.github.io/guarana/ in plain text. Updated 2026-11-13.

## What it is

- A downstream fork of Lichii (https://github.com/zortos293/Lichii). Lineage: Guarana <- Lichii <- Eglantine (https://github.com/Eglantine-Community/Eglantine) <- Eden (https://git.eden-emu.dev/eden-emu/eden) <- yuzu.
- Focus: laptops and handhelds without a gaming graphics card. Intel Arc integrated GPUs first, AMD Radeon integrated-GPU handhelds next.
- Work areas: frame pacing, frame generation by extrapolation, GPU fixes that show a measured gain on a verified scene, ThinLTO + PGO release builds.
- Tested platform: Windows 11 x64.
- Official download: https://github.com/karimalsalah/guarana/releases/latest (GitHub Releases only; the website never hosts downloads).

## What it is not

- It contains no encryption keys, no firmware and no games. Users dump them from a Switch 2 and games they own.
- It is not affiliated with, endorsed or sponsored by Nintendo, Intel, AMD, ASUS, Lenovo, Microsoft, MSI or Valve.
- It is not a general speed-up: the measured gain is from one scene on one laptop.
- It has not been measured by the maintainers on any handheld yet, nor on Linux, SteamOS or macOS.

## Measured results (with caveats)

- Machine for every row: Intel Core Ultra 9 285H, Intel Arc 140T, Intel driver 32.0.101.9175, Windows 11.
- Verified scene: The Legend of Zelda: Ocarina of Time, Hyrule Field. Global-memory routing fix (EDEN_NX2_GM=11), frame generation off: 14.75 -> 22.83 game fps. Foliage draw GPU time: 15.7 -> 5.8 ms.
- Play configuration, frame generation on: previous build 19.6 game fps; v20 about 26.7 game fps. Different spots, so not an A/B comparison of the builds.
- Game fps = frames per second the game itself renders. Generated frames are never counted.
- Verified scene = the run's scene check passed before frames were counted.
- Caveat: one laptop, one scene. Other games, scenes, drivers, power limits and machines will differ.
- Third-party reports (other builds, not verified by us): about 30 fps in Ocarina of Time on a ROG Xbox Ally X (Ryzen Z2 Extreme, Radeon 890M-class GPU; https://github.com/zortos293/Lichii/issues/1433), where the report's author found the emulator's GPU threads waiting on each other, not the GPU, to be the limit; Arc 140V 22-24 fps during gameplay (AlfaDev23's build).
- Machine-readable data: https://karimalsalah.github.io/guarana/data/benchmarks.json

## How frame pacing and frame generation work

- Frame pacing is how evenly frames reach the screen. With frame generation on, each generated frame keeps the screen for an equal share of the time between real frames. Some micro-stutter remains; the fix in progress is a presenter locked to the display's vblank (16.67 ms per frame at 60 Hz).
- Frame generation extrapolates: after the game renders a frame, the next frames are predicted by moving its pixels along the game's own motion vectors. Nothing waits for a future frame, so no latency is added (interpolation would have to hold the newest frame back). The HUD is handled separately so it doesn't smear.
- Motion data is wired up for Ocarina of Time only so far. Frame generation pauses while HDR output is active.
- What the global-memory routing fix does: shader loads from global memory used to search every bound buffer at run time; with EDEN_NX2_GM=11, buffer base addresses are computed once and each load searches only the buffers its address can come from.

## Known issues

- Pacing micro-stutter: fix in progress (vblank-locked 16.67 ms presenter).
- First visit to an area hitches while shaders compile; later visits load them from the cache.
- Intel driver cache race: fix in progress.

## Setup (Windows 11)

1. Download the latest release from https://github.com/karimalsalah/guarana/releases/latest.
2. Extract the whole archive into a folder you can write to.
3. Start the emulator and point it at keys, firmware and games dumped from hardware you own.
4. Switches are off unless set. Add EDEN_NX2_GM=11 to nx2_switches.txt next to the emulator. For frame generation: Graphics settings > Enable Frame Generation on, Target Frame Rate 60, and EDEN_NX2_EXTRAPOLATE=1 (Ocarina of Time only).
5. Let shaders compile (first visits hitch), then send a device report: https://github.com/karimalsalah/guarana/issues/new?template=device-report.yml

### Intel Arc 140T (Tested)

Page: https://karimalsalah.github.io/guarana/devices/arc-140t.html

Arc 140T is the only GPU Guarana has measured so far. Every number on this site comes from one laptop with a Core Ultra 9 285H, Arc 140T and Intel driver 32.0.101.9175.

- Global-memory routing fix (EDEN_NX2_GM=11), frame generation off: 14.75 → 22.83 game fps in Hyrule Field, The Legend of Zelda: Ocarina of Time. The foliage draw fell from 15.7 to 5.8 ms of GPU time.
- Play configuration with frame generation on: the previous build ran at 19.6 game fps and v20 at about 26.7. They were measured at different spots, so they are not an A/B comparison.
- One laptop and one scene. Laptops with other power limits or memory will land elsewhere, so send a report either way.
- GPU architecture: Xe-LPG+ (Arrow Lake-H integrated graphics, with XMX matrix engines)
- GPU size: 8 Xe-cores, up to 2.35 GHz on the Core Ultra 9 285H
- Memory: No dedicated video memory: shares system RAM (dual-channel DDR5-6400 or LPDDR5X-8400, depending on the laptop)
- Power: Core Ultra 9 285H: 45 W base, up to 115 W turbo. Each laptop sets its own sustained limit.
- Found in: Laptops with Core Ultra 200H processors that list Arc 140T graphics, such as the Core Ultra 9 285H
- Driver: Intel graphics driver for Windows; our numbers use 32.0.101.9175
- Note: A fix for an Intel driver cache race is in progress.

## FAQ

### What is Guarana?

Guarana is a free, open-source Nintendo Switch 2 emulator tuned for integrated GPUs: Intel Arc iGPU laptops and handhelds first, AMD Radeon iGPU handhelds next. It is a fork of Lichii, which builds on Eglantine, Eden and yuzu. The work focuses on frame pacing, frame generation and GPU fixes measured on real hardware, tested on Windows 11.

### Is there a Switch 2 emulator for Intel Arc integrated graphics?

Yes: that is what Guarana is tuned for. On a Core Ultra 9 285H laptop with Arc 140T (driver 32.0.101.9175), the global-memory routing fix took Ocarina of Time's Hyrule Field from 14.75 to 22.83 game fps with frame generation off. That is one laptop and one scene; see the device pages for other Arc GPUs.

### Does it run on handhelds like the ROG Ally, MSI Claw or Legion Go?

Not measured by us yet. Handhelds are a target (Intel Arc ones first, then AMD Radeon ones). One handheld has a third-party report: about 30 fps in Ocarina of Time on a ROG Xbox Ally X, on the upstream Lichii tracker (#1433). The Arc 140V GPU of the MSI Claw 8 AI+ has another third-party report, on a different build. Every other handheld is untested: see the device pages and send a report.

### Will it run on a low-end PC?

It is built for PCs without a gaming graphics card, but Switch 2 emulation is still demanding. Our only measured result is 22.83 game fps in an outdoor scene on a Core Ultra 9 285H laptop. Older or lower-power integrated GPUs are untested, so we can't promise playable speeds there. Try it and send a report.

### How does frame generation work, and does it add input lag?

Guarana extrapolates: after the game renders a frame, it predicts the following frames by moving pixels along the game's own motion vectors. Nothing waits for a future frame, so it adds no latency, unlike interpolation, which has to hold the newest frame back. The HUD is handled separately so text and menus don't smear. Motion data is wired up for Ocarina of Time only so far, and frame generation pauses while HDR output is active.

### Does Guarana have smooth frame pacing?

Smooth pacing is the goal, and it isn't finished. With frame generation on, each generated frame keeps the screen for an equal share of the time between real frames, but some micro-stutter remains. The fix in progress is a presenter locked to the display's vblank, so frames change every 16.67 ms on a 60 Hz screen. Separately, the first visit to an area can hitch while shaders compile.

### What does game fps mean on this site?

Game fps is how many frames per second the game itself renders. Generated frames are not counted, so frame generation can't inflate the number. With frame generation on, you see more frames than the game fps.

### Does Guarana include keys, firmware or games?

No. You dump keys, firmware and games from a Switch 2 and games you own. The project doesn't help anyone get them elsewhere, and requests for them are closed.

### Is Guarana legal?

Guarana is open-source software (GPL-3.0-or-later) that contains no Nintendo keys, firmware or games, and it isn't affiliated with Nintendo. Laws on emulation and on copying your own games differ by country, so this isn't legal advice. See the legal page.

### What do I need to run it?

A Windows 11 x64 PC or handheld with a Vulkan-capable GPU and a current graphics driver, plus your own keys, firmware and games. Our measurements come from a Core Ultra 9 285H laptop with Arc 140T. There is no measured minimum yet. On Windows with 16 GB of RAM, enlarge the page file.

### Which graphics driver should I use?

A current stable driver from Intel or AMD. Our Intel numbers use 32.0.101.9175, and a fix for an Intel driver cache race is in progress. Results can change between driver versions, so put your exact version in every report.

### Which games work?

Every number on this site comes from The Legend of Zelda: Ocarina of Time, which is also the only game with extrapolated frame generation so far. Guarana follows upstream Lichii, so other games may run, but we haven't measured them. Tell us what you find.

### Why does it stutter the first time I enter an area?

The emulator compiles shaders the first time it meets each effect, and the first visit pays for that. Later visits load them from the cache. A remaining pacing micro-stutter has its own fix in progress.

### Does it run on Linux, SteamOS or macOS?

We test on Windows 11 only. If a release lists builds for other systems, we haven't tested them; reports from Linux and Steam Deck users are welcome.

### How is Guarana different from Lichii?

Guarana is a downstream fork focused on integrated GPUs. It adds the global-memory routing fix, extrapolated frame generation and frame pacing work, and changes ship only with a measured gain on a verified scene. Fixes that aren't specific to integrated GPUs should go to upstream Lichii first.

### How do I send a device report?

Open the device report form on GitHub. Include your device, CPU and GPU, driver version, power mode, the game and spot you tested, the switches you set, and the game fps. Untested devices need this most.

### Can AI coding agents contribute?

Yes. AGENTS.md explains the rules, issues labeled agent-ready are scoped for agents, every pull request is built and tested free in CI, and an opt-in debug MCP server lets an agent read status, frame times, screenshots and logs from a running game. See Contribute.

### Is Guarana affiliated with Nintendo, Intel or AMD?

No. It is an independent open-source project. Product names are used only to say what it runs on.

### Where is the official download?

Only on the GitHub releases page of github.com/karimalsalah/guarana. This website links there and never hosts downloads itself. Ignore other sites that offer Guarana downloads.

- Changes that aren't specific to integrated GPUs go to upstream Lichii first.
