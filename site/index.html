Switch 2 emulation tuned for integrated GPUs

For laptops and handhelds without a gaming graphics card: Intel Arc first, AMD Radeon handhelds next. A fork of Lichii that works on frame pacing, frame generation and GPU fixes, and publishes every number with the machine it came from.

Get it in three steps

  1. Download Guarana Setup

    Get Guarana-Setup-<version>.exe from the GitHub releases page, the only official download. It installs for your user, without admin rights.

  2. Bring your own keys, firmware and games

    Dump them from hardware you own. Guarana Setup finds them on your PC with your consent. None are included.

  3. Play

    On a Windows integrated GPU, Ocarina of Time sets up its own frame pacing; on an Intel iGPU without matrix cores, such as the Arc 140T, it also turns frame generation on (since v20.2). The first visit to each area hitches once while shaders compile.

Stuck? Stutter, black screen, crash, the FAQ, or ask in the Discord.

Will it run on my PC?

Windows x64 is the tested platform (Linux and macOS builds are on Releases, untested on these devices); you need an x86-64 CPU with AVX2 and a Vulkan driver. 16 GB of RAM is below the comfortable floor, because the integrated GPU shares it. Tested means we measured it. Community reports means someone else did, on their build. Untested means nobody has reported yet, so your report counts.

Coming in v20.3

Merged on main, listed under Unreleased in the changelog, and in the next release.

  • Frames on time in Ocarina of Time on Windows integrated GPUs, by default: the screen copy runs on a queue of its own, and the frame budget no longer raises the resolution into the GPU time the cadence frees. The numbers are at the top of this page.
  • FLUID at 120 Hz, opt-in: a frame every refresh of a 120 Hz display. In Hyrule Field on the Arc 140T, five swapchain images took slots on time from 790–801 to 1134–1137 of 1200.
  • Fewer freezes: pointer-slot compute rebuilds compile on a worker, which removes 2.5–3.4 s freezes in Hyrule Field (upstream Lichii #995).
  • A device profile in the log: GPU, CPU cores, RAM, power, display refresh and a device class, in one line you can paste into a report. No default changes with it yet.
  • Launcher: an opt-in three-level Game Booster that undoes everything when the game exits, and Windows integration: game files open from Explorer, guarana:// links, taskbar progress and opt-in notifications.
  • Checkable downloads: a signed build provenance attestation on every release file.

Test it on your device in 10 minutes

No code and no debugger. Every GPU except one laptop's Arc 140T is untested, so any report is a first data point. "It does not run" is a result too.

  1. Install and leave the settings alone

    Run Guarana Setup, plug in the charger and keep the defaults (mode Auto).

  2. Stand in Hyrule Field

    In your own copy of Ocarina of Time: 30 seconds to settle, then one more minute. Take one screenshot.

  3. Send it

    Press Share on the card the launcher shows after the game, or fill in the form yourself. You read it and you press Submit; nothing is sent for you.

Send a device report The call for testers

Leave out keys, firmware, games, saves, shader caches and logs with your name in them. The full protocol: docs/TESTING.md. A scripted run can set a record on the records board.

Contribute, with or without an AI agent

The rules are the same for people and agents, and a person owns every pull request. You don't need a fast PC: CI builds every pull request on Linux and Windows and comments a Windows test build.

Find work and claim it

Start with a good first issue, an agent-ready task with its acceptance test, or a problem with a number on Open wins. Comment /claim on the issue: it is labelled and assigned to you for 72 hours, and for as long as an open pull request links it.

How to contribute

Bring your agent

One sentence in your clone starts Claude Code, Codex, Gemini CLI, Cursor, Copilot, Windsurf, Aider or Cline. AGENTS.md has the rules, and an opt-in debug MCP server lets an agent read frame times, screenshots and logs from a tester's running game. Disclose AI help with an Assisted-by: trailer.

How frame pacing and frame generation work

Frame pacing

Pacing is how evenly frames reach the screen. Thirty frames spaced 33.3 ms apart feel smoother than forty that arrive in uneven bursts. The FLUID presenter shows one frame per display slot, timed to the display's vblank; since v20.2 it is on by default for Ocarina of Time on Windows integrated GPUs, and v20.3 gives its screen copy a queue of its own so it no longer waits behind the game's rendering.

Frame generation by extrapolation

After the game renders a frame, Guarana predicts the next ones by moving its pixels along the game's own motion vectors. Extrapolation shows each real frame as soon as it is ready, where interpolation would hold it back until the next one exists. The HUD is kept apart from the 3D image, so text and menus don't smear. Generated frames make motion smoother, not input faster. Motion data is wired up for Ocarina of Time so far.

Measured GPU fixes

A change ships when it shows a measured gain on a verified scene. The global-memory routing fix took the Hyrule Field foliage draw from 15.7 to 5.8 ms on Arc 140T. Experiments stay behind switches that are off by default.

Optimized builds

Release builds are compiled with ThinLTO and profile-guided optimization (PGO).

Known issues, in the open

  • First visit to an area hitches while shaders compile; later visits load them from the cache, and a headless warm-up can build the cached ones ahead of time.
  • Until v20.3 is released, v20.2.0 still flips about 200 frames per 10 s late in Hyrule Field on the Arc 140T; the v20.3 defaults bring that to 0.
  • Intel driver crash when the pipeline cache is saved during builds (IGCIT #1614): open on the roadmap. EDEN_NX2_CACHE_SAFE=1 avoids it but can deadlock at boot, so it stays off.
  • No input latency figure is published yet.

Bring your own keys, firmware and games

Guarana contains no encryption keys, no firmware and no games. Dump them from a Nintendo Switch 2 and games you own. We don't help anyone get them elsewhere, and issues or pull requests that ask for them or share them are closed.
