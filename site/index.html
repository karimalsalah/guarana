Switch 2 emulation tuned for integrated GPUs

Guarana is a fork of Lichii for laptops and handhelds without a gaming graphics card. Intel Arc iGPUs come first, AMD Radeon iGPU handhelds next. The work goes into frame pacing, frame generation and GPU fixes, and we publish what we measure with the caveats.

What the fix does: shader loads from global memory used to search every bound buffer at run time. With EDEN_NX2_GM=11, buffer base addresses are computed once and each load searches only the buffers its address can come from. Game fps counts only frames the game renders; generated frames never count.

Bring your own keys, firmware and games

Guarana contains no encryption keys, no firmware and no games. Dump them from a Nintendo Switch 2 and games you own. We don't help anyone get them elsewhere, and issues or pull requests that ask for them or share them are closed.

How frame pacing and frame generation work

Frame pacing

Pacing is how evenly frames reach the screen. Thirty frames spaced 33.3 ms apart feel smoother than forty that arrive in uneven bursts. With frame generation on, each generated frame keeps the screen for an equal share of the time between real frames. Not finished: a presenter locked to the display's vblank, so frames change every 16.67 ms at 60 Hz, is in progress to remove the micro-stutter that remains.

Frame generation, without added latency

After the game renders a frame, Guarana predicts the next ones by moving its pixels along the game's own motion vectors. Because this extrapolates forward instead of waiting for a future frame, it adds no latency. The HUD is kept apart from the 3D image, so text and menus don't smear. Motion data is wired up for Ocarina of Time so far.

Measured GPU fixes

A change ships when it shows a measured gain on a verified scene. The global-memory routing fix took the Hyrule Field foliage draw from 15.7 to 5.8 ms on Arc 140T.

Optimized builds

Release builds are compiled with ThinLTO and profile-guided optimization (PGO).

Known issues, in the open

  • Pacing micro-stutter: the fix (a vblank-locked 16.67 ms presenter) is in progress.
  • First visit to an area hitches while shaders compile; later visits load them from the cache.
  • Intel driver cache race: a fix is in progress.

Set up in five steps

  1. Download the latest release

    Get it from the GitHub releases page, the only official download.

  2. Extract the whole archive

    Unpack everything into a folder you can write to.

  3. Add your own keys, firmware and games

    Start the emulator and point it at keys, firmware and games dumped from a Switch 2 and games you own. None are included.

  4. Turn on the measured settings

    Switches are off unless set. Add EDEN_NX2_GM=11 to nx2_switches.txt next to the emulator. For frame generation, turn on Enable Frame Generation in the graphics settings, set Target Frame Rate to 60 and add EDEN_NX2_EXTRAPOLATE=1 (Ocarina of Time only).

  5. Let shaders build, then report

    The first visit to each area hitches while shaders compile. Play a while, then send a device report with your game fps.

Help make it fast on your hardware

For people

Send a device report, run the benchmark harness on your machine, or pick an issue. Every pull request is built and tested for free in CI and gets a Windows test build linked on the pull request, so you don't need a fast PC to contribute code.
