# PR title
nx2: call the GPU memory registry and address space listeners outside their locks

# PR body
## What

Fixes the permanent silent guest freeze on Ocarina of Time ocarina warps (issue #1158, also matches the RADV freeze thread #1070) — and by construction a whole family of deadlocks reachable any time a guest thread registers GPU memory while the GPU thread is backing sparse blocks.

## Root cause (from gdb thread stacks of a frozen session)

A closed lock cycle across three threads, reproducible within 60–120 s on a warp to a temple area (Temple of Time / Desert Colossus), RX 7900 GRE, RADV 26.2.6, builds 125–130 and current nx2:

- **Guest CPU core** (SubRegisterMemory → `Nx2GpuMemoryRegistry::MapAt`): holds the registry's `mutex`, and the listener (`nvhost_as_gpu::Nx2Map`) queues a GMMU map on the GPU thread via `GPU::MapInOrder` → `ThreadManager::PushCommand(block=true)`, **waiting** for it — still under the registry's `mutex` (and under nvhost_as_gpu's own `mutex` too).
- **GPU front thread**: blocked in `GpuSplit::Drain`, waiting for its back.
- **GPU back thread**: in `INx2GpuSession::BackSparseWrite` (a texture upload during the warp's garbage collection) → `Nx2GpuMemoryRegistry::BackSparse` → `nvhost_as_gpu::Nx2BackSparse`, **waiting** for the same mutex the guest holds.

Guest → GPU front → GPU back → registry mutex → guest. Video/audio freeze permanently, the emulator UI stays responsive, the log goes silent (no semaphore wait, no device loss), and a forced restart panics the game with 2010-0212 — which is only the consequence.

## The fix

Notify listeners outside the locks:

- `Nx2GpuMemoryRegistry` records the mapping/unmap/sparse bookkeeping under `mutex`, copies the listener set under the lock, releases it, and only then calls the listeners (new `NotifyListeners` helper). `AddListener`'s replay of existing mappings stays under the lock, where it remains atomic against `MapAt`.
- `nvhost_as_gpu` does its SMMU bookkeeping under its `mutex` and queues the GPU-thread work (`GPU::MapInOrder` / `GPU::RunInOrder`) only after releasing it — in `Nx2Map`, `Nx2Unmap`, `Nx2Release`, `Nx2Sparse` (create and destroy) and `Nx2SparseTile`.

Both halves are needed: with only the registry half, the same cycle re-forms one level down, with the guest holding `nvhost_as_gpu`'s `mutex` in `Nx2Map` while the GPU back waits for it in `Nx2BackSparse` (verified with a second stack capture).

## Verification

- Reproduces ~100% before (warp to a previously visited temple, 60–120 s in).
- After the fix: warp loops to Temple of Time and Desert Colossus, plus a long play session — no freeze (previously it never survived the first warp).
- The pipeline storm that triggers the window (async builds spiking to 1–2 s during the warp) still happens; only the deadlock is gone, so the fix does not mask the storm itself.
